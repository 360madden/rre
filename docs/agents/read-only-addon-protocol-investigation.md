## Reuse-first outbound experiment

The best clipboard experiment avoids assuming either VMware host clipboard sharing or vncdotool CutText. A reviewed addon Copy action writes a known payload in the guest; an existing GuestSession PowerShell command reads only the expected payload, writes it to a unique bounded guest file, and existing copy_from_guest transfers it to a fresh host destination. Windows documents [Get-Clipboard -Raw](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/get-clipboard?view=powershell-5.1) as returning multiline text intact. This is documented feasibility, not Lab2 runtime proof. If using a [Windows.Forms Clipboard fallback](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.clipboard.gettext?view=windowsdesktop-10.0), STA is an explicit requirement.

First require fresh VM/game/source/loaded-version evidence and a metadata-only receipt binding RIFT and PowerShell user/session, apartment state and interactive clipboard visibility. Same session ID is necessary evidence, not by itself proof of the same window station/desktop; the known-payload transfer is the decisive test. Use a fresh expected framed payload or two distinct known Copy outputs; never print/store an unrelated clipboard value. Require a settled Copy-complete UI acknowledgement, exact type/size/schema/build/session validation, UTF8 byte length and SHA equality at guest/host, create-new files, identity rechecks and exact-path cleanup. Bound clipboard-busy read retries under the same click; never repeat a click automatically. SavedVariables remains the qualified fallback until this passes.

## Proposed minimal RREC1 receipt, not implemented

Use fixed allowlisted operations (capture/probe/lookup/export), version/schema, addon-load identity, monotonic operation sequence, player/role/context, start/completion clocks, status/reason, completeness/drop counts, payload byte length and a deterministic fingerprint. Render compact completion status in the UI. A consumer-owned nonce can be required only after an actual inbound binding path exists; do not claim current fixed buttons deliver a host nonce. A Lua-generated session token is a correlation value, not authentication.

For bulk export, choose one bounded complete document with exact start/end markers and a strict schema before adding chunking. If measured carrier limits require parts, add bounded part/count/order, whole-document length/fingerprint, duplicate/replay rejection and final assembly validation. Do not invent cryptographic authenticity: receiver-side SHA256 provides content comparison; no Lua SHA implementation was established here. Preserve old `latest` compatibility and prior-good captures. No arbitrary function names/code or game actions enter the protocol.

Reuse RR2's framing, independent process identity, clearing/epoch and advancing-clock concepts. The existing `RR2R1|JSON|ENDRR2R1` contract is capped8192bytes with exact fixed properties; its nonce is not authentication and its present fields are typed resources/context, not a general ability catalog. Publishing an RRE payload under that marker would violate ownership/schema. No RR2 source should be edited to accommodate RRE.

Offline gates: strict serializer/parser fixtures for versions/unknown or duplicate fields, malformed/oversize/truncated data, replay/wrong operation, bounds, false/zero, incomplete/error output, torn/changed frames, and old SavedVariables compatibility. Live gates depend on the chosen carrier: current loaded source, exact process/VM/build, visibly bound request, complete advancing observations, stale/wrong-player rejection, byte fidelity/cleanup and separate delivery/completion conclusions. No cast/server/freshness/restart qualification follows from a single transferred payload.

User subsequently suggested a memory-based bridge and asked whether to study feasibility first. The manager selected a short feasibility study before implementation. SC618 now owns that discriminator: locate/read RRE frames using an existing read-only tool if possible, identify marker/schema limits, and measure end-to-end latency rather than just read time. First bridge direction is addon → consumer. Host → addon memory writes/injection/debugger or automatic arbitrary commands are outside this design.

This investigation made no source/VM/game/provider changes. Two actual read-only built-in reasoning agents were used across SC616/617; Workbridge jobs are not model agents. No Ollama or FreeBuff.
