# SC-619 — One RRE modular host reader, offline core accepted

**Result:** RRE now owns one C# reader/core with a shared observation contract, source adapters, ability/context modules, and JSON output usable from PowerShell or C#. This0.1.0 milestone is an offline consumer: persisted RRECollector SavedVariables and replayed memory-scan artifacts. It does not acquire live RIFT memory or change Lab2's addon. The [usage/contract guide](../reader/README.md) contains commands and limits; the [source/build/test receipt](REA-RIFT-MODULAR-HOST-READER-2026-11-07.json) binds the accepted integration.

## What changed and why

- `reader/Rre.Reader`: one package-free .NET10 core/CLI; `IObservationSource` separates acquisition from normalized data and `ObservationModules` selects abilities/context. `capture`, `validate` and `doctor` share one entry point. JSON documents are one line, suitable for JSONL collection and `ConvertFrom-Json`. Output files publish atomically without overwrite.
- `tools/rre-reader-saved-snapshot.mjs`: a narrow data-only wrapper around the **existing** literal Lua parser and current Detail projection. It does not evaluate Lua or introduce another parser. It binds exact input bytes/hash, preserves false/zero and context shape, and separates capture-producing version from saved-root version.
- `MemoryScanSource`: strict offline replay of the original Reader's scan JSON and SC618 fixture frames, using explicit expected session/sequence, exact schema, canonical raw hex, bounded contexts, frame lengths, part assembly and unique IDs. Only the experimental fixture producer is accepted; a production RRE addon frame remains a separate contract/gate.
- `reader/Rre.Reader.Checks` and `tools/tests_reader`: package-free C# checks, Node adapter/legacy compatibility tests and an explicit real-evidence integration command. No external dependency or shared environment was installed/changed.

The common envelope distinguishes source/provenance, host observation time, capture sequence, available modules and qualification. Missing optional data remains unknown. `complete` is scoped to requested modules: fixture ability data can be complete while an all/context request is incomplete because its source has no context. Every current output sets live/freshness/process-build/atomic/restart qualification false. A structurally valid persisted capture is not promoted to a current game observation.

## Review findings resolved

Two real built-in agents independently read the new code without writing files or running Lab2. Concrete fixes include canonical original-Reader hex/window handling, enforcing the same body validation through direct assembler calls, module-scoped completeness, separate root/capture versions, and preserving the producer's scalar ability target. The existing crosswalk intentionally redacts private targets for historical research reports; the new local consumer merges the original bounded scalar back without changing that older tool. Unsupported target shapes fail rather than disappearing. Public module building also validates input records before claiming structure verification.

The SC618 memory fixtures came from the older **sanitized projection**, which omitted target IDs. Their54-ID transfer proof remains valid for that projection. The new saved adapter preserves an additional observed target; integration compares every fixture field and separately checks that the saved target survives. No private target value is copied into this tracked report.
