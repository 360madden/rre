# SC-103 — Historically published Legendary selection mechanism and current API visibility boundary

**November 3, 2026 UTC. Status:** accepted as a *historical publisher-source lead*, **not** proof of current character selection, present client rule, alternate ability ID or eligibility.

## Source evidence

- **Original publisher announcement:** RIFT / Trion Worlds, **September 15, 2016**, [Starfall Prophecy Preview: Legendary Powers](https://store.steampowered.com/news/posts/?appids=39120%2C222960&enddate=1474583424), preserved by Steam news (page lines 99–107). It describes Legendary as **chosen upgrades of existing abilities**, selected on level progression from **66 through 70**, up to **three per Soul** subject to invested Soul points, with choices **specific to an individual role slot**. These are historical launch-era mechanics, not reverified 2026 gameplay rules.
- **Local historical Protector's Fury evidence:** [variant-gap audit](REA-RIFT-SPELLCASTING-SC103-PROTECTORS-FURY-VARIANT-GAP-2026-11-03.md) identifies one historical static exact ID `A0E2112FD6FE262EE`, with no current `Inspect.Ability.New.Detail` return. [Physical tooltip metadata](REA-RIFT-SPELLCASTING-SC103-PALADIN-TOOLTIP-METADATA-2026-11-02.json), SHA-256 `d9008e8d64860858299ea975817263c8cd2373d81f703c448b7ea2c7c8a65c43`, records both Normal and Legendary descriptive text; the screenshot does not expose an alternate ID or selected Legendary state.
- **Specific publisher Live corroboration:** The official [RIFT 4.5 Live patch notes of July 11, 2018](https://store.steampowered.com/news/posts/?appids=39120&enddate=1531522420&feed=steam_community_announcements) (Live block lines 408–416; Paladin line 496, **not the Prime duplicate**) describe Legendary Protector's Fury damaging attackers while active and a **30%** chance to trigger Light's Balm on the Warrior after damage. This matches the historical original Paladin tooltip's retaliatory damage/Light's Balm effects, strengthening its *mechanics* provenance. It discloses **no ability ID**, role assignment, level or current-client variant selector.
- **Existing modern saved API documentation:** `Inspect.Ability.New.Detail` reports 34 return fields, fully serialized by RRECollector; no documented `rank`, `legendary`, `variant`, or `unlockState`. [Current stored documentation and limits](REA-RIFT-SPELLCASTING-SC103-RUNTIME-ABILITY-DETAIL-DOCS-2026-11-03.md), text SHA-256 `73d52608384c39888bd4328143b092bb1f0f3de7d3e0eb8f001118a1438b753d`.
- **Related current stored List documentation:** An already installed `RiftReader2Casting` saved `Inspect.Ability.New.List()` textual documentation (181 characters, SHA-256 `70213977f890f88dfcbe42c8b6fc7ec10d0d98dcaf56e2e83faa308dcda9e219`), describing a table of IDs for *available* abilities. This alone does not define learned, eligible, castable or Legendary membership, nor role sensitivity. The earlier current-client capability probe kept `Inspect.Ability.New.List/Detail` as supported; specifically probed `Inspect.Soul.List/Detail` and `Inspect.Action.List/Detail` paths were absent. ## Narrow inference, not gameplay conclusion

A tooltip that prints *two possible descriptions* does **not** identify an active choice. In the 2016 system, Legendary assignment was a separate progression/Soul/role-specific selection. The historical Atank Soul Tree screenshot shows a displayed level 45 and 45/15/0 points, but **do not deduce actual maximum character level or eligibility** from that alone: level scaling or mentoring status was not independently qualified. No currently proven alternate Protector's Fury ID exists. A Legendary form might share an ID and change behavior based on role state; that possibility is neither proven nor excluded by the existing data.
